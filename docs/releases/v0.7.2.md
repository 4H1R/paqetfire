# PaqetFire v0.7.2

This release updates the bundled Paqet engine to a leaner packet path.

## Engines

- **Paqet** is updated to the [4H1R/paqet](https://github.com/4H1R/paqet)
  fork's `v1.0.0-alpha.21-a2`, which uses less CPU and memory on the client:
  - packets are built and parsed with a dedicated encoder and decoder, and
    received data goes to KCP without an extra copy;
  - each proxied connection uses one goroutine fewer, and idle connections
    release their copy buffers;
  - SOCKS5 UDP no longer allocates per datagram, and a slow new destination
    no longer stalls traffic to the others;
  - memory freed after a burst of traffic goes back to Windows once the
    connection goes quiet.

  The wire protocol is unchanged, so existing servers keep working without an
  update; they still need the same key, KCP mode, MTU, and FEC settings as the
  client. Linux servers gain the most from updating to a2 themselves: it adds a
  memory-mapped AF_PACKET backend and fixes capture-buffer drops under bursts.
- Xray-core 26.10.31, ProxiFyre 2.6.4, and Windows Packet Filter 3.6.2 are
  unchanged.

## Notes

- Paqet now logs a warning when the KCP MTU plus 60 bytes of IP/TCP headers
  (80 with IPv6) is larger than the network adapter's MTU. Packets that size
  are dropped, so the tunnel connects but stalls once data flows. If you set
  **MTU** under Advanced transport, keep it at 1440 or less on a standard
  1500-byte connection.
