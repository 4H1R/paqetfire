# PaqetFire v0.7.1

This release updates the bundled engines, moves Paqet to the 4H1R fork, and
fixes hotspot sharing and the OpenVPN exit.

## Engines

- **Paqet** is now the [4H1R/paqet](https://github.com/4H1R/paqet) fork,
  `v1.0.0-alpha.21-a1`: upstream alpha.21 plus faster, more resilient
  transport and fixes to the client connection pool and configuration
  loading. The wire protocol is unchanged, so existing servers keep working
  without an update; they still need the same key, KCP mode, MTU, and FEC
  settings as the client.
- **Xray-core 26.10.31**, a security update over 26.3.27.
- **Psiphon** is pinned to a newer console client (binaries commit
  `b710e31`). If you already downloaded Psiphon, the exit shows it as not
  downloaded after upgrading; choose **Download Psiphon** again.
- ProxiFyre 2.6.4 and Windows Packet Filter 3.6.2 are already current.

## Routing data

- Xray now ships the XTLS/Xray-rules-dat GeoIP Lite and GeoSite Standard
  files, so the bundled routing data is newer and the installer is smaller.
  Every category PaqetFire uses is still there. With the Iran — Direct preset,
  `geoip:ir` now covers the addresses suited to direct connections from Iran
  rather than strict geolocation.
- GeoIP Lite has no per-country data, so the exit country on Overview now
  comes from the routing data Xray is using. With updated routing data (the
  default), every country is shown; with bundled data, the exit address is
  shown without a country instead of a wrong one.

## Fixes

- Phones and other devices joining the Windows Mobile hotspot get an address
  while PaqetFire is connected. DHCP replies to them were previously captured
  into the route.
- OpenVPN 2.7 cannot authenticate to Paqet's SOCKS5 listener, so the exit
  never connected with it. Routing → Exit proxy now links the OpenVPN 2.6
  installer directly and reports an installed 2.7 as unusable, with the
  reason, instead of failing at connect.
