# PaqetFire v0.7.3

This release stops PaqetFire from failing when another program already uses
one of its local ports, such as 1080.

## Local ports

- **The engines' loopback ports are picked automatically.** Paqet (1080),
  Xray (1081), Xray statistics (10085), and the Psiphon exit (1084) keep
  their usual ports while those are free. When another program holds one, or
  Windows reserves it for Hyper-V, WSL, or Docker, PaqetFire moves it to a free
  port before connecting. Only this computer can reach these ports, so there
  is nothing to configure.
- The chosen ports are remembered across restarts, so the kill switch keeps
  working after the broker restarts. **Diagnostics** list the ports in use and
  say when they moved.
- The read-only "Local SOCKS5 endpoint 127.0.0.1:1080" field is gone from
  **Network interface**, since nothing outside PaqetFire can use that
  listener.

## Sharing

- The LAN and hotspot share ports may now be any port from 1024 to 65535,
  including 1080, 1081, and 1084; PaqetFire moves its own listeners out of the
  way.
- If another program already uses a share port, connecting stops with a
  message that names the port, instead of Xray failing to start.

## Fixes

- When Xray is slow to start with downloaded routing data, the automatic retry
  with the bundled data no longer fails because the just-stopped Paqet still
  held its port.

## Engines

- Paqet `v1.0.0-alpha.21-a2`, Xray-core 26.10.31, ProxiFyre 2.6.4, and Windows
  Packet Filter 3.6.2 are unchanged.
