# Psiphon as an exit proxy chained behind Paqet

An exit proxy runs as a fourth, optional engine that reaches its network only through Paqet's loopback SOCKS5 listener, and Xray sends routed TCP to it as one more outbound. Running Psiphon beside Paqet instead, connecting directly, would expose its traffic to the local network that Paqet exists to avoid, and many Psiphon protocols are filtered there. Chaining keeps every Xray rule in front of the exit, so direct, blocked, and DNS traffic are unchanged, and only what would have gone to Paqet moves. The exit engine joins the controller's carrier side: it starts after Paqet, before capture, and a route that asked for an exit is never reported connected without it, so Connect fails rather than leave from the Paqet server. UDP stays on Paqet because Psiphon's local SOCKS5 proxy relays TCP only; blocking UDP instead would break calls and games for a difference in exit address. We ship Psiphon's public network parameters, as community clients do, and accept that Psiphon may change or limit them.
