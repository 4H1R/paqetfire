# Exit engines are optional downloads, and OpenVPN binds an adapter instead of routing the computer

Exit engines are not part of the installer: Psiphon is downloaded by the broker on request from a commit-pinned URL and accepted only with its pinned size and SHA-256, and OpenVPN is the user's own OpenVPN Community installation. Bundling them made every install carry about 30 MB and, for OpenVPN, a kernel driver that most users never need, and shipping OpenVPN's drivers would make PaqetFire responsible for their installation and upgrades. Psiphon keeps the guarantees of a bundled engine because the digest is pinned in code and re-checked before every start; OpenVPN cannot be pinned, so the broker, which runs it as SYSTEM, only accepts an installation that nobody but SYSTEM, Administrators, or TrustedInstaller can modify. OpenVPN joins the exit slot Psiphon defined: it reaches its server only through Paqet's authenticated SOCKS5 listener, starts after Paqet and before capture, and is stopped and restarted with the transport. Because OpenVPN works at the IP layer, we considered letting it set the default route, as a stand-alone VPN would; that changes the whole computer, defeats per-application capture and LAN or hotspot sharing, and leaks routed traffic directly when the tunnel drops. Instead it owns a dedicated TAP adapter, pushed routes and DNS are ignored, its only route is a metric-9999 default on that adapter, and Xray's exit outbound binds its sockets to the adapter, so routed traffic fails closed when the tunnel is down. An imported .ovpn is reduced to an allowlist of client options, because options such as `up` or `plugin` would run arbitrary programs as SYSTEM for any interactive user who can reach the broker.
